# claude (Claude Code CLI) quirks

Read this when an agent on this tool misbehaves, or before spawning it for the first time on a new box. Tool behaviour goes stale: every entry carries the date it was last observed; re-check against `--help` before relying on one.

Covers headless claude seats and the orchestrator's own Claude Code session. The approval-hook trap is in the runbook (§4). Working looks like a spinner with an advancing timer; idle is an empty prompt or "? for shortcuts".

## Costliest first

**Right after a spawn the claude seats show `blocked: launch_blocked`, no session id, no transcript; codex and agy seats are fine.** A worktree of a repo never opened in Claude Code on this box stops at the startup folder-trust dialog ("Quick safety check: Is this a project you created or one you trust?"), which the autonomy flag does not bypass and whose default is "No, exit". You may accept it yourself only for a worktree you just created from the repo under work: send Down then Enter (`hcom term inject <name> $'\x1b[B'` then `hcom term inject <name> --enter`; a bare Enter exits the agent). For any other directory, leave the seat parked and ask the human. Run `hcom list | grep launch_blocked` after every gate spawn, and detect it from that status, never from CPU. Prevention is a human step: open `claude` once in the repo root and accept. A seat held here for long starts on a stale pinned head, so re-pin its brief. _(observed 2026-10; unverified)_

**Claude seats sit `listening` (or `inactive: failure:rate_limit`) with no verdict file; several at once.** The account hit its session usage limit, which stops every claude seat's turn together; screens show "session limit · resets HH:MM" or "Usage limit reached". Check verdict files first (a seat may have finished before the limit), then for each seat with outstanding work, wait for the reset, then inject a recovery line ("re-check on-disk state, redo only what did not complete, deliver"). A "99% of session limit" banner on a fresh spawn means the next seats will park: spend the remainder on seats closest to a verdict. _(observed 2026-09; unverified)_

**A headless orchestrator hit the usage limit; `hcom r <name>` fails "No conversation found", and its seats keep reporting into silence.** A headless bus-spawned claude leaves no resumable transcript, and sends to its dead name drop without error. Do not retry the resume: reclaim your own identity, check disk, write a resume brief pointing at the status file, decisions and live seat names, start a new orchestrator, and have it tell every live seat "orchestrator is now @<new>". This only works if the status file's next steps were current. _(observed 2026-10; unverified)_

**Usage windows burn out in a day, or reviewers run on a different model than the gate config says.** A hand-written `hcom 1 claude …` spawn inherits the session's default model and effort; only the spawn script applies the gate's model knob. Put `--model <m> --effort <e>` after the prompt and before `--go` (another order printed the args and launched nothing), export `HCOM_CLAUDE_ARGS="--effort <e>"` to cover every claude spawn, give in-process subagents an agent type that pins both, and confirm on the seat's header with `hcom term <name> | head`. _(observed 2026-09; unverified)_

## Dialogs that park a seat

**Fresh seat goes quiet before its first report; screen asks "Allow reads outside the working directories?".** The brief reads files outside `--dir`. Granting that read is a human step: log the seat under decisions-needed and tell the human, or kill the seat and respawn it with the brief's inputs copied under its directory, which is the better fix either way. _(observed 2026-09; unverified)_

**Seat finished a turn and shows `listening` (or `tui:prompt-has-text`) with an old State Age; a queued message is never read.** It is sitting on a feedback / "bug report drafted" dialog. Dismiss with `hcom term inject <name> 0 --enter`, wait a few seconds, then re-hand the task by a second inject. At every round tally, treat a dialog or typed text older than about 30 minutes as dead, not slow. _(observed 2026-09; unverified)_

**Screen shows "Session paused — safeguards flagged this session" with a numbered choice and "will retry".** A provider safeguard paused the seat. The choice in that dialog is the human's: do not answer it, log it under decisions-needed with the seat name and what it was doing, and tell the human. Write review scopes as the behaviour to verify because that is the clearer brief, not to avoid a flag; if the work is not honestly defensive, stop. _(observed 2026-10; unverified)_

## The orchestrator's own session

**The orchestrator stops handling watcher wakes and bus messages.** It ended a phase on a blocking question dialog, which freezes its turn loop and also hides the message text above it from the human. Ask in plain text with numbered options, log it under decisions-needed, keep the watcher armed and end the turn. _(observed 2026-10; unverified)_

**Auto mode denies an agent spawn, a merge or an external write that a standing instruction permits.** The classifier judges the live session and does not read grants stored in memory or notes. Ask the human for the grant in-session and say why; never rewrite or reshape a command to get past a denial. If an orchestrator-seat spawn is denied, orchestrate from the current session. **Write every launch as one bare `hcom` command from the start** (no leading `cd … &&`, no pipe, no trailing `; echo`; use `--dir` for the directory), one launch and one purpose per command, because that is the form an `hcom` allow-rule is written for. If a launch is denied anyway, the answer is still the in-session grant, not a different spelling. _(observed 2026-10; bare-launch form observed 2026-09 on hcom 0.7.25; unverified)_

**A watcher you just started is gone, and the tool call returned exit 144.** A kill by command-line pattern matched its own shell, because the shell's command line contained the pattern; it also matches any agent whose command line mentions it. Never kill by pattern: find the PID (by `HCOM_INSTANCE_NAME` as in hcom.md for an agent, `pgrep -x <process name>` for anything else), `kill <pid>`, and confirm with `ps -p <pid>`; check the watcher survived with `ps -p <watcher pid>`. _(observed 2026-10; unverified)_
